# Project Overview

"bet" (placeholder name) is a mobile-first web gaming platform — Aviator, Ludo, Chicken Road, Dice —
using **virtual coins only** in v1 (no purchase, withdrawal, or transfers). The server decides every
outcome and every balance; outcomes are provably fair. Full design: `/design` skill. Original
product intent: `/product-spec` skill. Scope checklist: `REQUIREMENTS.md`.

# Commands

Run from the repo root unless noted. Node ≥22 (`.nvmrc` = 24), pnpm 10.

- Install: `pnpm install`
- Start Postgres + Redis: `pnpm db:up` (stop: `pnpm db:down`) — needs a Docker runtime
- Dev (frontend :3000, backend :4000): `pnpm dev`
- Build all: `pnpm build` · Lint all: `pnpm lint` · Typecheck all: `pnpm typecheck`
- Test all: `pnpm test` · Backend e2e: `pnpm --filter backend test:e2e`
- One package: `pnpm --filter <frontend|backend|@bet/shared> <script>`
- Single backend test: `pnpm --filter backend exec vitest run src/path/file.spec.ts`
- Prisma (from root): `pnpm --filter backend db:migrate` · `db:generate` · `db:studio`
- Format: `pnpm format` (check only: `pnpm format:check`)

# Architecture (brief)

- `frontend/` — Next.js 16 App Router, React 19, Tailwind 4. Player UI + `/admin`. Never computes
  outcomes or balances; renders server state.
- `backend/` — NestJS 12 (ESM). Modules: auth, users, wallet (ledger), fairness, games/{aviator,
  dice,chicken-road,ludo}, admin, audit. REST + Socket.IO gateways.
- `packages/shared/` (`@bet/shared`) — types, enums, pure game/fairness math used by both sides.
  Build it (`pnpm --filter @bet/shared build`) before typechecking dependants.
- PostgreSQL (Prisma) is the only source of truth for coins. Redis holds rebuildable live state
  (round state, pub/sub, rate limits, locks).
- Games touch coins only via the wallet service API (`placeBet` / `settleBet` / `refundBet`).

# Money and Fairness Invariants

IMPORTANT: violating these is a critical bug, even with virtual coins.

- Coin amounts are integer minor units (`bigint`, 1 coin = 100). Never `number` floats for money.
- Ledger is double-entry and append-only: entries sum to zero; no UPDATE/DELETE; fix with reversals.
- Every coin-moving endpoint requires an idempotency key.
- Outcomes come only from the fairness module (committed seeds / hash chain). Never `Math.random()`
  for game outcomes; use `node:crypto`.
- Never trust client values for multipliers, timestamps, outcomes, or balances.

# Conventions

- TypeScript strict everywhere. No `any` in new code; use `unknown` and narrow.
- Backend is ESM with `nodenext`: relative imports need the `.js` suffix (`./app.module.js`).
- Validate every request DTO at the controller boundary; keep business rules in services.
- Shared types go in `packages/shared`, not duplicated in frontend/backend.
- Layer conventions live in `.claude/rules/` and load automatically by path.

# Gotchas

- Next.js 16 differs from older versions. Before using a Next API, read the matching guide in
  `frontend/node_modules/next/dist/docs/`. `frontend/AGENTS.md` is regenerated by `next dev`; keep it
  committed.
- Frontend typecheck runs `next typegen` first — `LayoutProps`/`PageProps` are generated globals.
- Prisma 7: config is `backend/prisma.config.ts` (loads `.env` via dotenv); the schema datasource has
  no `url`. The client is generated to `backend/src/generated/prisma` and needs the
  `@prisma/adapter-pg` driver adapter. Run `db:generate` after schema changes.
- Backend listens on 4000 (Next uses 3000).
- Docker on macOS is OrbStack; if `docker` isn't on PATH in a non-login shell, use
  `~/.orbstack/bin/docker`.
